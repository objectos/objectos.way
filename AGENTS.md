# AGENTS.md

Objectos Way: build web apps using only Java.

JPMS module `objectos.way`, target JDK 25 (`JAVA_RELEASE := 25`).
The root project is built by a hand-written `Makefile` — no Gradle/Maven.
`make` requires `JAVA_HOME` and fails fast otherwise.

## Build / test commands (reference)

- `make compile` → classes in `work/main`; `make test`; `make re-test` (force rerun).
- `make dev` runs `objectos.way.dev.DevStart` on port 8003.
- `make all` = `mysql7-start test mysql7-stop`: the test suite expects a local MySQL/MariaDB (see `make/mysql7.mk`). It also uses TestNG, H2, MariaDB, and Playwright (headless) for script/browser tests.
- `make jar`, `make javadoc`, `make install`, `make publish`.

## Tests

- Runner is `objectos.way.RunTests` (`test/objectos/way/RunTests.java`). TestNG scans packages `objectos.*` and `objectox.*`; the only CLI argument is the output directory, so a single test/class **cannot** be selected from the command line. Every test method gets a 5 s timeout.
- `test/` mirrors `main/` package names; test-only helper packages are `test/objectos/y` and `test/objectos/util`.
- Tests for non-exported packages need `TEST_ADD_EXPORTS` / `TEST_ADD_READS` entries in the root `Makefile`. Add them when testing a new internal package.

## Layout & module boundaries

- `main/` — production sources (module `objectos.way`). `test/` — TestNG tests.
- Exported API (`main/module-info.java`): `objectos.css`, `objectos.dev`, `objectos.html`, `objectos.html.format`, `objectos.html.markup`, `objectos.html.stream`, `objectos.http`, `objectos.lang`, `objectos.script`, `objectos.way`.
- `objectos.internal`, `objectos.way.dev`, and the whole `objectox.*` tree are **not exported** but still shipped in the jar. The jar excludes only `objectos/way/dev` and `objectos/way/DevBoot.class` (`JAR_EXCLUDES`).

## Generated code — never hand-edit

- `main/objectos/script/JsLibraryGenerated.java` is generated from `main-js/way.js` by `ScriptLibraryGen.java` (`make script-gen`).
- `main/objectos/css/CssProps.java` is generated by `CssPropsGen.java` (`make css-props-gen`).

## Objectos HTML

Allows for declaring and generating HTML using pure Java.

Public, exported API:

- `objectos.html`: main API. Most users only need this package.
- `objectos.html.format`: formatting Objectos HTML documents.
- `objectos.html.markup`: interfaces backing the declarative API.
- `objectos.html.stream`: interfaces backing the streaming API.

Implementation classes live in:

- `objectox.html`
- `objectox.html.attr`
- `objectox.html.elem`
- `objectox.html.format`
- `objectox.html.markup`
- `objectox.html.stream`

## TDD

This project is developed using TDD:

- Write tests first.
- Write tests first.
- Never write production code when there's no test code.
- The tests should drive the design of the class being developed.
- Don't limit yourself to the happy path; think hard on what ways can a functionality fail.
- Don't limit yourself to unit tests; include integration tests if you feel the need for them.
- Before modifying an existing production class, ensure that test coverage for the class is adequate.

## Code style

### Class declarations

When adding methods to a class, keep them sorted. First, by access level:

- public
- default (package-private) access
- protected
- private

Then sorted alphabetically.

### Method invocations

Avoid having more than one method invocation in the same statement or sub-statement.

The following should be avoided:

```java
return append(s.subSequence(start, end));
```

The innermost method invocation should be declared as a local variable instead:

```java
final CharSequence sub;
sub = s.subSequence(start, end);

return append(sub);
```

Also, the use of method chaining should be minimized.

### License header

Every Java source file starts with the Apache 2.0 header; the conventional copyright line is `Copyright (C) 2022-2026 Objectos Software LTDA.` New files must include it.
